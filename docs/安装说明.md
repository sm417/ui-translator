# 界面翻译 · UI Translator

Chrome 扩展。**只翻界面文字，自动跳过代码块。**

Chrome 自带翻译是"整页送去翻"：代码、缩进、变量名一起被翻乱，布局跟着塌。这个插件反过来做——先判断哪些是界面文本，只送那部分；`<code>` / `<pre>` / `<kbd>` / 代码编辑器 / 已是中文的内容一律不动。

---

## 一、安装（30 秒，只需一次）

1. 打开 Chrome，地址栏输入 `chrome://extensions/` 回车
2. 右上角打开 **开发者模式**（Developer mode）开关
3. 左上角点 **加载已解压的扩展程序**（Load unpacked）
4. 选择文件夹：`F:\界面翻译插件\extension`（**选到 extension 这一层，不要选它的上一层**）

装好后建议点一下工具栏的拼图图标，把「界面翻译」钉到工具栏上。

> 没有图标是正常的——这个版本没做图标文件，Chrome 会给一个默认的灰色图标。
> 不影响任何功能。

---

## 二、使用

打开任意英文网页（Jupyter、Python 文档、论文页面都行）→ 点工具栏图标 → 点 **翻译此页**。

- 点一次之后，**之后打开的页面会自动翻译**，不用再点（见下面「自动翻译」）
- 想还原当前页 → 再点一次（按钮会变成「还原原文」）
- 想快 → **Alt+T** 直接翻译 / 停止，不用开弹窗
- 鼠标悬停在译文上 → 弹出原文（默认开启）
- 译文底部会提示翻了多少处

三个选项：

| 选项 | 说明 | 建议 |
|---|---|---|
| 引擎 | 腾讯翻译（免费）/ 大模型 | 日常用腾讯，够了 |
| 显示 | **中英对照（默认）** / 直接替换 | 对照靠得住；界面太密时可切替换 |
| 新页面自动翻 | 打开的新页面自动翻译，页面里动态加载的新内容也会补翻 | 默认关闭；点过一次翻译后自动打开 |

**中英对照怎么显示的**：原文一行，译文一行接在下面，译文略小、颜色略淡。原文不删，随时能对照；点「还原原文」一次性全部撤回。

### 自动翻译（切到新页面也翻）

只有一条规则：**点是开始，再点是停止。**

| 动作 | 结果 |
|---|---|
| 点「翻译此页」或按 Alt+T | 翻当前页，**同时打开自动模式** |
| 之后再打开 / 切换到任何网页 | 自动翻译，不用再点 |
| 再按一次 Alt+T（或点「还原原文」） | 还原当前页，**同时关掉自动模式** |
| 弹窗里取消勾选「新页面自动翻」 | 只关自动模式，当前页保持已翻状态 |

自动模式会自动跳过这些情况，不会打扰你：

- **中文 / 日文 / 韩文页面**——不主动扫描（看 `lang` 属性；没有 `lang` 就采样页面文字判断）
- **后台标签页**——一次恢复十几个标签时不会同时发请求，等标签切到前台才翻
- **没东西可翻的页面**——静默跳过，不弹提示
- **自动翻译时没有「翻译中…」进度条**，只在完成后轻轻提示一句「已自动翻译 N 处 · Alt+T 停止」

> 想整站跳过？目前没做域名黑名单（避免多一个控件）。到那个页面按一次 Alt+T 就停了，代价是自动模式也一起停——回到需要的页面再按一次即可。

> 已经用过的旧设置会覆盖默认值。如果打开弹窗看到「显示」还是「直接替换」，手动切一次「中英对照」，之后会一直记住。

## 三、两个引擎的区别

**腾讯翻译（transmart）** — 默认，免 key、开箱即用。**6 批并发 × 每批 40 条**，300 条界面文字约 3.5 秒（实测数据见第六节）。术语质量在免费接口里算好的（实测 `Kernel` → 内核、`Run All Cells` → 运行所有单元格）。

**大模型（DeepSeek 等）** — 要填 API Key。句子更顺、术语更贴上下文，长段落明显更好。接口填 OpenAI 兼容格式即可：

```
接口：https://api.deepseek.com/v1
模型：deepseek-chat
Key ：sk-...
```

通义、Kimi、本地 ollama（`http://localhost:11434/v1`）同理。**Key 只存在本机 `chrome.storage.sync`，不外传。**

## 四、它不翻什么（这是重点）

自动跳过：

- `<code>` `<pre>` `<kbd>` `<samp>` `<textarea>`
- CodeMirror / Monaco 编辑器（Jupyter 的代码格、VS Code Web）
- `contenteditable` 区域
- `<svg>` `<canvas>` `<math>`
- 已经是中文的段落（CJK 占比 > 35% 直接放过）
- 纯数字、纯符号

会翻：

- 按钮、菜单、标签、提示文字
- 段落正文（渲染后的 Markdown 也翻）
- `title` / `placeholder` / `aria-label` / `alt` 属性——工具栏上那些只有图标的按钮，靠这个才翻得出来

## 五、排错

| 现象 | 原因 / 处理 |
|---|---|
| 点了没反应 | 刷新页面再点。`chrome://` 开头的页面不允许扩展运行，属正常 |
| 提示「不能建立连接 / Receiving end does not exist」 | 页面是在扩展安装之前打开的，里面没有翻译脚本。**已内置自动补注入**，正常情况下你感知不到；若仍报错，刷新页面即可 |
| 提示「这个页面不支持翻译」 | 系统页 / 扩展页 / 应用商店 / PDF 阅读器，这些 Chrome 不允许注入 |
| 提示「部分失败」 | 网络抖了，那几批保留原文，重试一次即可 |
| 换了新页面没有自动翻译 | 先看弹窗里「新页面自动翻」是否勾上。另外：中文/日文/韩文页面会被主动跳过；后台标签页要切到前台才开始翻 |
| 某个网站不想自动翻 | 在那个页面按一次 **Alt+T**（会还原该页并停止自动模式）；需要时再按一次恢复 |
| 某句 / 标题下面出现**两行一模一样的英文** | 引擎那次把原文原样吐回来了，而旧版把这个结果写进了缓存，于是这句话以后永远「翻」成英文。v1.2.1 已修：未翻译的结果不再进缓存，旧缓存整体作废。装好后重载扩展即可，无需手动清缓存 |
| 标题 / 摘要被**切成几截**，英文和中文交错、行高被撑开 | 旧版按「文本节点」逐块翻，PubMed 这种标题里夹 `<a>` `<i>` 的页面，一句话会被切成五六段各翻各的。v1.3.0 改成按块级容器整段翻，译文统一挂在原文下方；重载扩展后重翻即可 |
| 译文出现在页面很靠后的位置、跑到了别的元素里 | 同上，块级译文是**追加在容器末尾**的。若某个站点的容器带 `overflow:hidden` 固定高度，切换成「仅译文」模式即可（会用译文替换掉原文块） |
| 个别短句没被翻（仍是英文） | 引擎对「字母+数字」短 token（如 `net16`、`Layer 3`）是**确定性**不翻，不是抖动。实测重试 3 次结果完全相同，加补翻也没用。正常界面短语不受影响。占约 1% |
| 翻出来是机翻味 | 切「大模型」引擎，或改用中英对照 |
| 双语模式太占地方 | 对照模式每处文字占两行，密集工具栏会变高——这是对照的代价，切「直接替换」即可 |
| 想清掉旧译文缓存 | 弹窗右下角「清缓存」 |

> 重装或更新扩展后，**已开着的旧标签页第一次点会稍慢**——因为要先往页面里补注入脚本。之后就正常了，不用手动刷新。

## 六、速度：慢在哪里，改了什么（2026-11-11）

原来的实现是**一批一批排队**：每批 25 条，等上一批回来才发下一批。300 条要 12 个来回，串行约 14 秒。

实测下来，瓶颈不是批大小：

| 批大小 | 单批耗时 | 每条平均 |
|---|---|---|
| 25 条 | 1.2 s | 48.9 ms |
| 60 条 | 2.6 s | 44.1 ms |
| 100 条 | 5.4 s | 53.8 ms |
| 200 条 | 8.6 s | 43.2 ms |

批再大，每条的平均成本几乎不变（约 45 ms）——只是把等待时间堆进一次请求。**并发才是唯一有效的杠杆。**

| 方案（300 条全新文本） | 总耗时 | 每条 |
|---|---|---|
| 串行，每批 25 条（旧） | ≈14 s | ≈47 ms |
| 并发 2，每批 60 条 | 8.3 s | 34.6 ms |
| **并发 6，每批 40 条（现用）** | **3.5 s** | **≈12 ms** |
| 并发 8，每批 40 条 | 3.1 s | 12.7 ms |
| 并发 10 | 3.1 s | 10.5 ms |

并发 6 已接近收益上限，再往上提升有限、被限流风险变大，所以定在 6（宽基 300 条连跑 5 轮，零失败）。

三个具体改动：

1. **并发调度**——改成「工作池」：6 条流水线同时跑，谁空了谁去领下一批，不再排队等。
2. **逐批实时写回**——以前要等所有批次全部回来才动手写页面，所以前几秒页面「没反应」。现在一批回来就先写这一批，**约 0.4 秒就出第一批译文**，其余边翻边显示。
3. **`busy` 改为重试**——接口排队时会返回 `ret_code: "busy"`。旧代码把它当失败，整批退回有道**逐条串行**翻译：60 条要 36 秒，这才是「卡很久」的真正原因。现在退避重试（300 / 600 ms），实测 300 条零失败；真要兜底时，有道也改成 3 条并发，不再串行。

顺手还提了 DOM 扫描：`title` / `placeholder` / `aria-label` / `alt` 由扫四遍整棵树改成扫一遍；可见性与「跳过」判断加了按元素缓存（同一个父元素常被多个文本节点共享，原来重复算）。

**一个已知的引擎限制**：带「字母+数字」混合 token 的短句（如 `net16`、`Layer 3`），腾讯接口会**确定性**地原样返回、不翻译。实测单条重试 3 次、整批重发 3 轮，结果一字不差，所以补翻逻辑没有意义、也没有加。真实界面短语（`Run All Cells`、`Kernel`、`Save As`）不受影响，实测 100% 翻出。这类漏翻约占 1%。

## 七、自检记录（2026-11-11 实测）

接口连通性（本机国内网络实测）：

| 接口 | 结果 |
|---|---|
| 腾讯 transmart | ✅ 批量 200 条可用，`ret_code=succ` |
| 有道 aidemo | ✅ 单条可用，作兜底 |
| Edge / Bing 免费接口 | ❌ HTTP 404，已下线，弃用 |
| Google Translate | ❌ 国内不可达，弃用 |

功能测试（jsdom 真跑 `content.js` + 真实网络请求）：

- 测试 0：不手动设 `User-Agent` / `Referer` 时接口照常返回 `succ`（浏览器会丢弃这两个头，已确认不影响）
- 测试 1：**15/15** —— 按钮/标签/placeholder/title 已翻；`<pre><code>`、CodeMirror、`<kbd>`、中文段落、纯数字全部原样；还原后逐字回到原文
- 测试 2：**5/5** —— 3 处相同文字只发 1 条；长段落自动拆段；双语模式插入译文节点且原文保留
- 测试 3：**7/7** —— 模拟「页面在扩展安装前打开、收不到消息」，验证会补注入一次并自动重试
- 测试 4：**13/13** —— 对照模式专项：原文/译文包在同一个 `.uizh-pair` 里（flex 工具栏中只占一个位置）；还原后 `.uizh-pair` 全部消失、文字逐字复原
- 测试 5：**11/11** —— 并发对位专项：300 个元素**逐一核对自己那条译文，零错配、零遗漏**；3 处重复只发 1 条；长段落拆 3 段后拼回与原文**逐字一致**；代码块未动；实测峰值 6 批同时在飞；真实网络 240 条 2.9 秒、成功率 98.8%
- 测试 6：**11/11** —— 后台专项：`busy` 退避重试后成功；400 类错误不重试；有道兜底 5 条 410 ms（并发，非串行）；60 条全失败也只用 1.2 秒且正确上抛；缓存命中后**零网络请求**、返回结果一致
- 测试 7：**28/28** —— 自动模式专项：开着时英文页自己翻、关着一个请求都不发、中文页不主动扫（无 `lang` 时靠采样判定）、点一次即写入自动开关、还原即关闭、弹窗勾选立即生效、后台标签页延后到可见、关闭后不再跟随新内容（并有反向用例证明该判定不是假通过）
- 测试 8：**13/13** —— 未翻译防污染专项：引擎原样返回时不进缓存（下次换正常引擎能拿到真译文）、「只差一个句号」的英文同样不算翻译、页面侧不插入纯英文的第二行、原节点带首尾空白也不误判；反向对照：真给中文时必须插入（证明前面的断言不是假通过）。在修复前的代码上跑同一份测试只有 **3/13** 通过，确认它抓得住这个 bug

清单合法性：`chrome --pack-extension` 实际打包通过（产出合法 CRX3），说明 Chrome 接受这个清单。

> 注：官方新版 Chrome 已禁用命令行 `--load-extension`，所以自动化只能做到「打包校验」，实际加载需在 `chrome://extensions/` 手动点。

弹窗布局：Chromium 无头截图核对，无换行错位、无截断。
